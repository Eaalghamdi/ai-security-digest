# AI Security Digest — 2026-06-14

**Today's themes:** AI agent infrastructure is under sustained attack from multiple angles — a new "Agentjacking" technique exploits the implicit trust coding agents place in MCP-sourced error telemetry, while a critical RCE vulnerability chain in LangGraph exposes self-hosted agentic deployments to full server takeover. In the legal arena, Google filed the first-ever lawsuit against a threat actor specifically for weaponizing its own AI, marking a new front in the AI security arms race.

### [Targeting World Models to Compromise Robot Learning Pipelines](https://arxiv.org/abs/2606.09499)
*Ethan Rathbun, Ahmed Agha, Saaduddin Mahmud, Christopher Amato, Alina Oprea, Eugene Bagdasarian — arXiv:2606.09499 — submitted 8 Jun 2026*

This paper introduces a novel supply-chain poisoning vector targeting world models — the learned simulators that generate synthetic training data or simulated environments for robot learning. By poisoning the world model rather than the final training data, an attacker can inject backdoor behaviours that survive into deployed robotic policies even when the visible ground-truth training data appears clean. The attack is uniquely stealthy because it operates at an abstraction layer that most security reviews do not audit, and it generalises across any pipeline that uses world models for data augmentation or sim-to-real transfer.

### [Quality-Diversity Evolution for Discovering Diverse Vulnerabilities in LLM Safety](https://arxiv.org/abs/2606.00801)
*arXiv:2606.00801 — submitted ~1 Jun 2026*

This work applies MAP-Elites quality-diversity evolution at the semantic level — evolving human-interpretable attack *strategies* rather than raw token sequences — to automatically discover a diverse portfolio of jailbreaking techniques. Running on GPT-4o-mini, Claude 3.5 Sonnet, Gemini 2.0 Flash, and Devstral-small-2, the framework exposes distinct vulnerability profiles across model families, revealing that each model has its own "safety fingerprint" of weaknesses. The contribution matters because diversity-aware red-teaming finds classes of attacks that uniform optimisation misses, giving safety teams richer coverage before deployment.

### [Cross-Generational Transfer of Adversarial Attacks Reveals Non-Monotonic Safety Alignment in LLMs](https://arxiv.org/abs/2606.00813)
*arXiv:2606.00813 — submitted ~1 Jun 2026*

Using MAP-Elites automated red-teaming on four generations of Google's Gemma family, this paper shows that safety alignment does not improve monotonically across successive model generations. Attacks evolved against Gemma 1, 2, and 3 transfer to Gemma 4 at only 14–18%, while cross-generational transfer among older versions runs at 44–46% — a surprising non-linearity that suggests each new generation introduces novel, uncharted safety weaknesses even as it fixes old ones. For practitioners, this means that red-teaming the *current* generation with attacks calibrated on *prior* generations gives false confidence; each release requires fresh adversarial evaluation.

## Blog posts

### [A Fake Bug Report Hijacks Your AI Coding Agent — and Nothing Catches It](https://tenetsecurity.ai/blog/agentjacking-coding-agents-with-fake-sentry-errors/)
*Tenet Security — 12 Jun 2026*

Tenet Security disclosed "Agentjacking": attackers craft malicious Sentry error events using only a publicly discoverable DSN (write-only key found in browser JS or GitHub) and inject attacker-controlled instructions that AI coding agents — Claude Code, Cursor, Codex — retrieve via the Sentry MCP integration and execute without question. In controlled validation across more than 100 organisations, Tenet achieved an 85% exploitation success rate; exfiltrated data included AWS keys, GitHub tokens, and full git credentials. The attack bypasses EDR, WAF, IAM controls, and VPN because the agent performs only operations it is legitimately authorised to do — no policy boundary is crossed. Sentry acknowledged the issue but declined a root-cause fix, calling it "technically not defensible" at the platform level, and shipped only a content filter for the known payload string — a pattern that will fail against the first mutation.

## News

### [Agentjacking Attack Tricks AI Coding Agents Into Running Malicious Code](https://thehackernews.com/2026/06/agentjacking-attack-tricks-ai-coding.html)
*The Hacker News — 12 Jun 2026*

The Hacker News covered Tenet Security's Agentjacking disclosure, documenting how the MCP trust model in AI coding agents creates an unbounded prompt-injection surface via any connected tool that ingests untrusted external data. At least 2,388 organisations were found to have injectable Sentry DSNs discoverable via public GitHub search. The article highlights that even explicit system-prompt instructions to ignore untrusted data failed to prevent exploitation — pointing to a fundamental architectural problem rather than a configuration gap. Any team running AI coding agents connected to error-tracking, log-analysis, or issue-tracking MCP tools should treat those integrations as trusted-execution entry points and audit them accordingly.

### [LangGraph Flaw Chain Exposes Self-Hosted AI Agents to Remote Code Execution](https://thehackernews.com/2026/06/langgraph-flaw-chain-exposes-self.html)
*The Hacker News — 12 Jun 2026*

Researcher Yarden Porat disclosed three now-patched vulnerabilities in LangGraph — the multi-agent orchestration framework built on LangChain — including a critical chain leading to unauthenticated RCE. CVE-2025-67644 (CVSS 7.3) enables SQL injection via metadata filter keys in the SQLite checkpoint implementation; chaining it with CVE-2026-28277 (CVSS 6.8), unsafe msgpack deserialization on checkpoint load, yields remote code execution in self-hosted deployments. A third flaw, CVE-2026-27022 (CVSS 6.5), allows RediSearch query injection to bypass access controls. All three are patched in langgraph ≥ 1.0.10 and the respective checkpoint libraries. Given LangGraph's wide adoption as a backbone for production agent systems, unpatched self-hosted deployments should be treated as critically exposed.

### [Google Sues Chinese Cybercrime Network for Using Gemini AI to Launch Mass Phishing Operation](https://www.helpnetsecurity.com/2026/06/12/google-china-based-cybercrime-network-lawsuit/)
*Help Net Security — 12 Jun 2026*

Google filed what appears to be the first lawsuit against a threat actor specifically for weaponizing a commercial AI system — in this case Gemini — to conduct large-scale fraud. The defendant, called the "Outsider Enterprise," operated a phishing-as-a-service (PhaaS) platform distributed via Telegram; members used Gemini to generate custom code for phishing pages and convert them into live scam sites. Between November 2025 and April 2026, Google identified more than 1.59 million fake URLs tied to the group; in a single two-week window in May 2026, the gang sent 2.5 million phishing SMS messages, generating 55,000 spam complaints — more than two per minute. The case is significant both as deterrence and as a public legal record establishing that misuse of a vendor's AI against that vendor's users constitutes actionable harm.
